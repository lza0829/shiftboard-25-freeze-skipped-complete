# 06-shiftboard（交班台）

交班台 — 班次责任与在途批次交接：班次登记 → 在途批次归属 → 交班互斥办理 → 交班前后对账。

**不是** 多源 Feed 归并，**不是** 作业依赖编排，**不是** CDC 变更流，**不是** 质检签发，**不是** 数仓贴源/明细/汇总分层。  
**也不是** OA 考勤排班后台、电商订单、报表 CSV 看板。

## 启动

本地开发：

```bash
# 后端
cd backend
pip install -r requirements.txt
set DATA_DIR=%CD%\data
set FIXTURES_DIR=%CD%\..\fixtures
uvicorn app.main:app --host 127.0.0.1 --port 10600

# 前端
cd frontend
npm install
npm run dev
```

| 入口 | 地址 |
| --- | --- |
| 前端 | http://127.0.0.1:5600 |
| 接口 | http://127.0.0.1:10600 |

## 主链

登记班次与值班人 → 在途批次归属当前班次 → 发起交班（全仓同时仅一单进行中）→ 完成交班整批过户 → 交班对账报告与清单/批次同源

## 逾期冻结

- 批次可配置逾期时限（`POST /api/batches/{id}/overdue`）；检查任务（`POST /api/batches/checks/run`）到期把在途批次标冻结。
- **冻结落库形态：批次状态机增加「冻结」态**（未另建冻结登记表）；冻结批不得普通结清（`settle` 返回 409），不得进入新交班清单。
- 冻结出口只有两条：解冻（→ 待确认，`待确认` 仍不进清单）或报废。
- **发起快照固化形态：独立发起快照表 `handover_start_keys`**，逐条记录纳入键与排除键及原因；清单数与过户数同源。
- 发起时先落到期冻结再过滤；滤净后无可交键则拒绝发起（400）。
- 交班进行中清单内键被冻结：完成时整单失败，同一事务内检测、过户前判定，零半截过户。
- **裁决证明持久化**：快照表同行固化完成时重检结果（`recheck_outcome` / `recheck_status` / `rechecked_at`）；只读接口 `GET /api/handovers/{id}/adjudication` 返回纳入键、排除键及原因、重检结果，交班办理界面排除数与裁决证明字段均由其同源派生。

## 界面约定

页面文案全部中文；入口：总览 / 班次 / 在途批次 / 交班办理 / 交班记录 / 交班对账。
